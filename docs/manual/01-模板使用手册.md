## 1. 模板是什么、渲染链路怎么跑

铸版 ZHUBAN 是一个"**Word 模板 + JSON 数据 → docx / pdf 成品**"的渲染平台。你在 Word 里做好版式、留下占位符；业务系统或人工把数据以 JSON 投递进来，平台把占位符替换成真实内容，导出 docx，并可选转成 PDF。

整体链路：

```
你在 Word 里做好 .docx 模板（带 {{ 占位符 }}）
        │  上传到模板库（系统自动扫描占位符、生成变量清单与示例 JSON）
        ▼
业务方提交一份 JSON 数据
        │  投递即生成 POST /api/v1/generate
        │  （单份同步返回 / 批量异步出 zip）
        ▼
渲染服务（容器内 docxtpl + LibreOffice）
        │  ① 跨 run 合并预处理  ② 数据校验  ③ 占位符替换
        │  ④ 图片/二维码/富文本对象注入  ⑤ 转 PDF（如需要）
        ▼
产出 .docx（格式与模板完全一致）+ .pdf
```

**一条铁律先说清楚：模板是什么格式，输出就是什么格式。** 页面纸张、页边距、页眉页脚、表格线宽、字体字号、段落间距——全部继承自你的 .docx，平台不会"重排版"。所以版式问题 99% 出在模板本身，而不是渲染。

## 2. 如何准备一份 Word 模板（版式规范）

### 2.1 页面设置

在 Word「布局 / 页面设置」里定好，不要靠回车和空格撑版面：

| 项 | 建议 | 说明 |
| --- | --- | --- |
| 纸张 | A4（21cm × 29.7cm） | 涉密交付默认 A4；确需 A3/Letter 在文档里注明 |
| 页边距 | 上 2.54cm、下 2.54cm、左 3.17cm、右 3.17cm | 涉密报告常见上 3.7 / 下 3.5 / 左 2.8 / 右 2.6，按单位规范 |
| 页眉页脚 | 在「插入」里用真正的页眉页脚 | 不要在正文顶部手敲一行当页眉；跨页时手敲行不会自动重复 |
| 页码 | 插入 → 页码 → 页面底端居中 | 用 Word 域，不要手敲数字"1、2、3" |

> 渲染服务会**完整保留页眉页脚与页码域**。如果你在正文里手敲"第 1 页"，它永远是"第 1 页"。

### 2.2 表格规范（缺陷清单、明细表最爱漂移）

| 规范 | 怎么做 | 为什么 |
| --- | --- | --- |
| 固定列宽 | 选中表格 → 右键「表格属性」→ 列 → 指定宽度 → 勾"指定宽度" | 数据长短不一会把列挤变形，固定列宽是唯一可靠手段 |
| 不允许自动调优 | 表格属性 → 表格 → 选项 → 取消"自动重调尺寸以适应内容" | 否则 LibreOffice 渲染时列宽会漂移 |
| 允许跨页断行 | 行属性 → 勾"允许跨页断行" | 长描述跨页时不被硬切 |
| 表头重复 | 选中表头行 → 表格工具 → 布局 → 重复标题行 | 长表跨页自动重复表头 |
| 用真表格，不要用空格对齐 | — | 空格对齐在不同字体下会错位 |

### 2.3 字体规范

渲染发生在 **Linux 容器内的 LibreOffice** 里。容器预装的中文字体是 Noto Sans CJK（思源黑体族）与 Noto Serif CJK（思源宋体族），运维可额外挂载 simhei / msyh 兜底。

**可执行建议（按这套做，版式最稳）：**

| 用途 | 字体 | 字号 |
| --- | --- | --- |
| 正文 | 宋体（容器映射到 Noto Serif CJK） | 小四（12pt） |
| 一级标题 | 黑体（容器映射到 Noto Sans CJK Bold） | 三号（16pt） |
| 二级标题 | 黑体 | 四号（14pt） |
| 表格内文字 | 宋体 | 五号（10.5pt） |
| 表格表头 | 黑体 | 五号（10.5pt） |
| 页眉页脚 | 宋体 | 小五（9pt） |

**字体缺失回退的影响（重要）：**

- 如果你在 Windows 上用了容器里**没有**的字体（例如方正小标宋、汉仪旗黑、华文行楷），LibreOffice 会**静默替换**到兜底字体，字号不变但字形会变——表现为"我 Word 里看着是方正小标宋，导出 PDF 变成宋体了"。
- 这不是 bug，是容器字体库限制。解决办法二选一：
  1. 模板统一用"宋体 / 黑体 / 仿宋 / 楷体"这四种通用名，容器都能映射；
  2. 确实需要专用字体，联系运维把 .ttf/.ttc 挂到渲染容器的字体目录（参考《部署记录》），不要私自改模板指望渲染端补。
- **不要在占位符前后刷特殊字体。** 占位符那几个字用正文默认字体即可，否则替换后这段会带着一段"杂字体"。

## 3. 占位符书写规范（最容易踩坑的一章）

占位符本质是写在 Word 里的纯文本，例如 `{{ 项目名称 }}`。docxtpl 靠它定位替换。**最大的坑是：Word 会把一段文字拆成很多个 run（运行块），如果你敲占位符时中途切了字体、按了空格、加了批注或修订，`{{` 和 `}}` 就会被拆到不同 run 里，渲染时认不出来。**

### 3.1 正确写法

1. 在 Word 里**切到正文默认字体**（不要选特殊字体再敲）。
2. **一次性连续输入** `{{ 项目名称 }}`，中间不要停、不要退格重敲、不要改字号。
3. 占位符前后留一个空格与正文隔开，例如：报告编号 {{ 项目编号 }} 出具。

### 3.2 绝对不要做

| 禁止动作 | 后果 |
| --- | --- |
| 敲到一半切字体/改字号 | `{{` 与 `}}` 被拆 run，报 `template_invalid` |
| 给占位符加批注、开启修订模式 | run 被进一步拆碎 |
| 把占位符放在文本框 / 艺术字 / SmartArt 里 | 渲染管线扫不到，原样残留 `{{` |
| 占位符中间用全角空格 `{{　项目名称　}}` | 中间全角空格能识别，但建议半角，避免歧义 |
| 复制粘贴带格式的占位符 | 粘贴时把源格式带进来，可能拆 run；要"只粘贴文本" |

### 3.3 如何在 Word 里自查占位符是否被拆坏

1. 打开 `.docx`，点占位符那几个字。
2. 切到「开始」选项卡，观察左上角**样式框**：如果选中 `{{ 项目名称 }}` 时样式框在"正文"和别的样式之间跳，说明它被拆了。
3. 更可靠的办法：**直接删掉这几个字，重新纯文本敲一遍。** 这是处理 `template_invalid` 的标准动作。
4. 上传到铸版后，系统会跑一次扫描，**诊断（diagnostics）**里会明确告诉你"`{{ 项目名称 }}` 被拆到 3 个 run，已自动合并修复"或"for 标签未配对"。看到 warning 级的"已自动合并"一般能正常用；看到 error 级必须回 Word 改。

> 平台有"跨 run 合并预处理"，多数轻微拆 run 会被自动修复。但**不要依赖它**——能在源头写干净，就不要赌自动修复。

## 4. 占位符语法全量速查（Word 写法 + JSON 对照）

语法基于 Jinja2 / docxtpl。下表每一项都给出"Word 里怎么写"和"JSON 里对应什么数据"，可直接照抄。

### 4.1 标量文本

Word 里写：

```
{{ 项目名称 }}
```

JSON 对应：

```json
{ "项目名称": "某系统验收报告" }
```

- 键名允许中文，前后空格会被自动忽略。
- 普通字符串里的 `\n` 会被当作换行。

### 4.2 默认值（变量缺省时显示兜底文案）

Word 里写：

```
负责人：{{ 负责人 or "未指派" }}
```

JSON 对应（负责人为空时显示"未指派"）：

```json
{ "负责人": "张三" }
```

### 4.3 表格行循环（最常用，缺陷清单表）

在表格里：**第一行是表头，第二行是循环样板行**，在这一行首尾包 `{%tr for %}` / `{%tr endfor %}`。

Word 里写（表格第二行的两个单元格内）：

```
{%tr for item in items %}{{ item.name }}        ← 单元格1：循环开头 + 本格内容
{{ item.缺陷等级 }}{%tr endfor %}                ← 单元格2：本格内容 + 循环结尾
```

> 实际操作：把 `{%tr for item in items %}` 写在该行**第一个单元格开头**，把 `{%tr endfor %}` 写在该行**最后一个单元格末尾**；循环体内用 `{{ item.字段名 }}`。
>
> 也可以让标签**各占一整行**（上一行写 `{%tr for %}`、内容行照常、下一行写 `{%tr endfor %}`），
> 系统会自动把这种只放标签的行删掉，不会在成品里留空行。

JSON 对应：

```json
{
  "items": [
    { "name": "GB_6.2.1.1 密码安全", "缺陷等级": "高" },
    { "name": "DKY_01_01_03 SQL注入", "缺陷等级": "高" },
    { "name": "GB_7.5.6 无效指针使用", "缺陷等级": "中" }
  ]
}
```

- 渲染时样板行会按数组条数**一行一行复制**，最适合缺陷清单、明细表。
- 循环变量名 `item` 可自取，但要前后一致。

### 4.4 整段 / 整表循环（每个条目复制一整段+一张表）

Word 里写（段落级，不是表格行）：

```
{% for item in items %}
第 {{ loop.index }} 项：{{ item.name }}
{{ item.description }}
（这里可以放一张完整的子表格、一段说明，都会随每个 item 复制一遍）
{% endfor %}
```

JSON 对应：同 4.3 的 `items` 数组。

- 与 `{%tr %}` 的区别：`{%tr %}` 只复制表格里的一行；`{% for %}` 复制"段落 + 表格 + 一切"整块。

### 4.5 条件块（满足才显示）

Word 里写：

```
{% if 缺陷等级 == "高" %}
⚠ 本项为高风险缺陷，须在上线前整改闭环。
{% endif %}
```

JSON 对应：

```json
{ "缺陷等级": "高" }
```

- 比较值 `"高"` 会被系统提取为该字段的**枚举校验**：你提交别的值会被 `/validate` 拦下来
  （报错文案里会回显你实际提交的值）。字段正文里也用它（`{{ 缺陷等级 }}`）时，
  界面显示的是一个带候选值的输入框，而不是开关。
- 也支持 `{% if 变量 %}`（变量为真才显示）、`{% else %}`。

### 4.5b 嵌套循环（分组 → 组内明细）

一组一张表、表内再按条目循环，是最常见的两级结构：

```
{% for g in 分组 %}                      ← 段落级：每组一张表
{{ g.分组 }}（{{ g.条目 | length }} 项）
[表格第二行] {%tr for it in g.条目 %}{{ it.问题 }} … {{ it.建议 }}{%tr endfor %}
{% endfor %}
```

JSON：内层数组挂在**父项内部**，不是平级：

```json
{
  "分组": [
    {
      "分组": "账号与权限",
      "条目": [
        { "问题": "后台存在弱口令账号", "等级": "高", "建议": "强制改密并启用复杂度策略" },
        { "问题": "离职人员账号未回收", "等级": "中", "建议": "接入统一身份源" }
      ]
    }
  ]
}
```

- 系统会把 `g.条目` 识别为 `分组` 的一个**数组字段**，示例 JSON 也就按这个形状给出 ——
  照着填即可，不会出现「数据填了但表是空的」。
- 支持两级（父循环 + 子循环）。再深请拆成两张表。

### 4.6 图片占位

Word 里写：

```
{{ image_logo }}
```

JSON 对应：

```json
{
  "image_logo": {
    "type": "image",
    "src": "data:image/png;base64,iVBORw0KGgo...",
    "width": 40,
    "height": 40
  }
}
```

- `width` / `height` 单位是**毫米 mm**，不是像素。
- `src` 支持：`http(s)://` 外链，或 `data:image/png;base64,...`。
- 外链图片有安全限制：仅 http/https、超时 10 秒、单图 ≤ 5MB、默认拒绝回环/内网地址（可由管理员放开白名单）。
- 命名前缀约定：变量名以 `image_` 或 `img_` 开头，系统自动识别为图片。

### 4.7 二维码占位

Word 里写：

```
{{ qr_报告编号 }}
```

JSON 对应：

```json
{
  "qr_报告编号": {
    "type": "qrcode",
    "text": "AP-2026-001",
    "size": 25
  }
}
```

- `text` 是二维码里要编的内容（报告编号、URL 等）。
- `size` 是成品在文档里的**显示宽度（mm）**，二维码自动正方形。
- 变量名以 `qr_` 开头即识别为二维码。

### 4.8 富文本占位（markdown / 受限 HTML）

Word 里写：

```
{{ rich_修复建议 }}
```

JSON 对应：

```json
{
  "rich_修复建议": {
    "type": "markdown",
    "content": "- 采用国密算法\n- **密钥必须加密机分发**"
  }
}
```

- 支持 `type: "markdown"` 或 `type: "html"`。
- HTML 走白名单：允许 `b/strong/i/em/u/s/br/p/span/ul/ol/li/font` 与 `color`；事件属性、`javascript:` 一律清除。
- 变量名以 `rich_` / `html_` / `md_` 开头即识别为富文本。

### 4.9 签名 / 印章占位（V3，详见《03-签章与授权使用手册》）

通过在线编辑器插入"签名 / 印章"后，模板里会生成一个图片型占位块，**变量名即资源 ID**：

```
{{ sig_a1b2c3d4e5f6 }}     ← 一个已授权的手写签名
{{ seal_0f1e2d3c4b5a6 }}   ← 一枚已授权的公章
```

- 它们走和图片**完全相同的渲染管线**，版式不漂移。
- 数据里**不需要**手动给这个字段赋值——系统按资源 ID 自动注入 PNG。
- 前提：该签名/印章已通过审核、且对当前调用人已授权，否则生成时被拒（422 / 403）。

### 4.10 语法速查表（贴墙版）

| 能力 | Word 写法 |
| --- | --- |
| 文本 | `{{ 名称 }}` |
| 默认值 | `{{ 负责人 or "未指派" }}` |
| 表格行循环 | `{%tr for x in items %} … {{ x.name }} … {%tr endfor %}` |
| 整段/整表循环 | `{% for x in items %} … {% endfor %}` |
| 条件 | `{% if level == "高" %} … {% endif %}` |
| 图片 | `{{ image_logo }}` |
| 二维码 | `{{ qr_报告编号 }}` |
| 富文本 | `{{ rich_修复建议 }}` |
| 签名/印章 | 编辑器插入，占位名即 `sig_xxx` / `seal_xxx` |

## 5. 变量定义在哪里维护

模板上传后，系统通过扫描自动识别出一份"变量清单"。你可以在两个地方维护它：

### 5.1 模板详情 → 变量定义页

路径：**模板中心 → 模板库 → 点开某个模板 → 「变量定义」页签**（`/templates/:id/variables` 对应后端 `/templates/{id}/variables/meta`）。

在这里可以为每个变量补充元数据：

| 字段 | 作用 |
| --- | --- |
| 名称 | 占位符对应的键名（扫描自动带出） |
| 类型 kind | scalar / loop / condition / image / qrcode / richtext（扫描自动判定） |
| 默认值 | 缺省时的兜底文案 |
| 是否必填 | 必填项在 `/validate` 时缺失会报错 |
| 说明 | 给业务方看的字段解释，会显示在接入文档与示例 JSON 旁边 |

### 5.2 在线编辑器右侧 VariablesPanel

路径：打开模板 →「在线编辑」→ 右侧面板「变量」。这里和变量定义页是同一份数据（后端 `/templates/{id}/variables/meta`），改一处即同步。

### 5.3 变量元数据如何影响校验与示例

- 你标记为**必填**的字段，业务方投递 JSON 时缺了会被 `/validate` 拦下，返回 `data_invalid` 并指明 `path`。
- 条件块里的比较值（如 `== "高"`）会被自动收进该字段的 `enum`，业务方传"极高"会被拦。
- 系统据此自动生成一份**示例 JSON**（`sample_json`），在接入文档页和工作台里直接"填充示例"，业务方照着改就行。
- 你填的"说明"会出现在变量树里，降低业务方填错字段的概率。

> 变量元数据是"锦上添花"，不是"必须改"。哪怕你一个都不维护，模板也能跑——只是校验更宽松、示例更朴素。

## 6. 在线编辑器怎么用

路径：**模板中心 → 模板库 → 某个模板 → 「在线编辑」**（`/templates/:id/editor`）。

编辑器是一个块级可视化排版工具，不用回 Word 也能改模板。

### 6.1 能做什么

- **改段落 / 表格**：直接在画布上编辑文字、调整表格行列。
- **插入占位符**：工具条「插入占位符」下拉 → 选文本 / 图片 / 二维码 / 富文本 / **签名 / 印章**。
- **插入签名 / 印章**：选「插入签名」或「插入印章」→ 弹出小抽屉，只列出**已审核且对你可用**的素材 → 点选后在光标处插入一个图片占位块。
- **传资源**：右侧「资源」上传图片素材到当前模板（绑定模板生命周期的图片，区别于跨模板复用的签章库）。
- **实时预览**：编辑后约 1.5 秒防抖自动渲染右侧预览页图。

### 6.2 关键认知：apply 是预览，不扣签章次数

编辑器里的**实时预览（apply / preview）走的是"只看不花"通道**：

- 它会真实渲染出签章图给你看效果；
- 但**不消耗**该签名/印章的授权次数（不扣 `used_count`、不写 `grant.use`）。

真正扣次数发生在你**点「生成并下载」或业务方 `/generate` 实际产出 docx/pdf** 的时候。所以放心在编辑器里反复预览排版，不用心疼额度。

### 6.3 存版本、激活、回滚

- **保存**：编辑器「保存」会基于当前画布生成一个**新版本**（版本号语义化递增）。
- **激活**：新版本默认即激活；你也可以在「版本」页签里切换激活版本。
- **回滚**：某个新版本出问题，在「版本」页签一键回滚到上一个可用版本。
- 每一次版本变更都写审计日志（`template.version` / `template.rollback`）。

### 6.4 导出 docx 与 pdf

编辑器顶栏「导出」：

- **导出 docx**：拿到当前模板的 Word 文件（可下载回本地 Word 精修）。
- **导出 pdf**：这是**实际产出**（渲染容器真实转出来的 PDF），不是预览水印图——可用于核对 PDF 版式。

> 提示：预览页图带"铸版预览"斜向水印，仅供排版核对；要无水印成品请走「生成并下载」或 API。

### 7.1 模板里有哪些占位符（对应扫描结果）

| 占位符 | 含义 | 类型 |
| --- | --- | --- |
| `{{ 被测件名称 }}` | 被测系统/产品名 | 标量 |
| `{{ 被测件版本 }}` | 被测版本号 | 标量 |
| `{{ 项目编号 }}` | 报告编号（可用于文件名规则 `{{项目编号}}_审计报告`） | 标量 |

| `{{ 测试时间 }}` | 出具日期 | 标量 |

## 8. 常见问题 FAQ

### Q1：我在 JSON 里写了 `\n`，为什么换行没生效？

`\n` 只在**普通字符串值**里生效（渲染成 run 内换行）。如果你想要的是"另起一个段落"，用富文本 `{"type":"markdown","content":"行1\n\n行2"}`，或在模板里就预留两段。表格单元格内 `\n` 会换行，但不会改变列结构。

### Q2：我 Word 里是方正小标宋，导出 PDF 怎么变宋体了？

这是渲染容器字体缺失导致的静默替换。容器只有 Noto 宋/黑与运维挂载的 simhei/msyh。改用"宋体/黑体/仿宋/楷体"四种通用名，或联系运维把专用字体挂进渲染容器。详见 §2.3。

### Q3：表格列宽在 PDF 里漂移了。

回到 Word：选中表格 → 表格属性 → 列 → 逐列指定宽度 → 取消"自动重调尺寸"。模板里没锁列宽，渲染时会按内容自适应。详见 §2.2。

### Q4：上传模板报 `template_invalid`。

占位符被 Word 的 run 拆坏了。**标准处理：在 Word 里删掉这个占位符，切正文默认字体，纯文本重新敲一遍**，不要刷样式、不要加批注/修订，再重新上传。上传后看"扫描诊断"里是否还有 error 级提示。详见 §3。

### Q5：键名用中文会不会有问题？

完全没问题。`{{ 项目编号 }}`、`"项目编号": "AP-001"` 是这套系统的推荐写法。扫描、校验、示例 JSON 全链路都按中文键名工作。

### Q6：日期怎么格式化？

模板里写死格式即可，例如 `{{ 测试时间 }}`，业务方传 `"2026-10-18"`。要"二〇二六年十月十八日"这种中文格式，让业务方在 JSON 里直接传格式化好的字符串——模板渲染不做日期运算，它只是文本替换。

### Q7：图片不显示 / 尺寸不对。

- 不显示：检查 `src` 是不是合法的 http(s) 或 base64；外链图是否被内网/回环策略拦了（默认拒绝私网地址）；单图是否超 5MB。
- 尺寸不对：`width`/`height` 单位是**毫米**不是像素。传 `120` 是 120 毫米，会撑爆 A4。按版式换算（A4 宽 210mm，左右各留 30mm，正文区约 150mm）。

### Q8：PDF 和 docx 为什么长得不一样？

docx 是直接改 Word XML，版式与模板一致；PDF 是 LibreOffice 二次转换。两者在**字距、表格线、分页位置**上可能有细微差别。以 PDF 为最终交付物时，务必在编辑器「导出 pdf」里核对一遍成品，而不是只看 docx。

### Q9：条件块 `{% if 等级=="高" %}` 传了"极高"为什么报错？

系统把 `"高"` 提取成了该字段的枚举值。这是设计行为：确保报告里只出现你认可的等级词。要放开就改模板里的条件表达式，或在变量定义里调整。

### Q10：循环里某条数据缺了一个字段，整份报告都失败了。

这是 `/validate` 的保护行为——必填字段缺失会 422 并指出 `path`（例如 `items[2].mitigation`）。定位到对应记录补齐即可。若某字段允许空，在变量定义里把它设为非必填，或在模板里用 `{{ item.备注 or "" }}` 兜底。
