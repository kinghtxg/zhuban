# 03 · 签章与授权使用手册（V3）

> 适用对象：需要准备手写签名、电子公章，并在模板里安放、按规则授权他人使用的模板管理员与合规人员。
> 本手册口径与 V3 PRD、`server/internal/api/seal_handlers.go`、`grant_handlers.go`、`server/internal/sigauth/sigauth.go` 一致。
>
> **先划清合规边界（重要）：** 本产品的"电子签章"是**放进 Word 模板里的图片型版式元素 + 全程审计追溯**，**不是** CA 数字证书、不是 PDF 密码学签名、不接可信时间戳（TSA）。如需具备法定电子签名效力，请对接 CA 机构证书。

## 1. 签名与印章是什么

| 资源 | 是什么 | 存哪 |
| --- | --- | --- |
| 电子签名 | 一张透明底 PNG：手写签名图，或"签名 + 服务器时间"组合图 | 签章中心 → 签名库（跨模板复用） |
| 电子印章 | 一张红色 PNG：圆形/椭圆公章，或上传的章图 | 签章中心 → 印章库（跨模板复用） |

它们是**组织资产**，不是某个模板的附属物——做一次，所有模板都能引用。在渲染时，系统把资源 ID 解析成图片对象，走和普通图片**完全相同的管线**插入文档，因此**版式不漂移、不影响 docx 排版**。

## 2. 准备电子签名

路径：**签章中心 → 签名库 → 新建签名**（`/seals-center/signatures/new`），两种方式二选一：

### 2.1 上传透明底 PNG

- 要求：**透明底 PNG**（系统不做抠图合成，你必须自备透明底）。
- 白底实拍签名会被当成一张白底方块贴进文档，很难看。先在图片工具里抠成透明底再传。
- 建议尺寸：宽度对应文档里约 60mm，按 `signature_default_width_mm`（默认 60）插入。

### 2.2 文字生成签名

输入姓名，选一款内置手写字体，系统用 Pillow 实时渲染：

| 字体 id | 风格 |
| --- | --- |
| `ma-shan-zheng` | 马善政体（端正手写） |
| `liu-jian-mao-cao` | 刘建毛草（草一点） |
| `zhi-mang-xing` | 字芒星 |
| `long-cang` | 龙藏 |
| `dancing-script` | 英文手写花体 |

可选项：

- **带服务器时间**：在签名下方排一行小字，内容是**服务器当前时间**（精确到秒）。这是"服务器时间的图像展示"，**不是可信时间戳（TSA）**，文案里不要写"可信时间戳"。
- **组合图**：签名在上、时间在下，拼成一张图。
- **宽度 mm（文档显示宽度）**：签名插进 Word 后在版面里占多宽，系统设置 `signature_default_width_mm` 默认 **60mm**。这是版式尺寸，不是字体字号参数。

右侧实时预览，改字体/姓名即刷新。满意后保存。

## 3. 准备电子印章

路径：**签章中心 → 印章库 → 新建印章**（`/seals-center/seals/new`），同样两种方式：

### 3.1 上传印章图

要求**透明底 PNG**。

### 3.2 参数化生成红色公章

表单字段：

| 字段 | 说明 |
| --- | --- |
| 单位名称 | 环形排布的单位全名 |
| 印章名称 | 五角星下方的文字（如"公章""财务专用章"） |
| 形状 | `circle`（圆形）/ `ellipse`（椭圆） |
| 半径 mm（生成参数） | 印章图形本身的半径，**默认 20mm，取值范围 10–40mm** |
| 五角星 | 默认开启居中 |

右侧**红色印章实时预览**（红色 `#C8102E`，环形字沿弧排布，五角星居中）。满意后保存。

> **两个"宽度"别混为一个值：**
> - **生成半径 `radius_mm`**：上面这枚印章图本身画多大（默认 20mm，范围 10–40）。
> - **文档显示宽度 `seal_default_width_mm`**：印章插进 Word 模板后在版面里占多宽，系统设置默认 **40mm**。
> 生成半径决定图的内部分辨率观感，显示宽度决定它落在文档里的实际尺寸；二者是两回事，改一个不影响另一个。

## 4. 在模板里安放签名/印章

### 4.1 操作

1. 打开模板的**在线编辑器**。
2. 工具条「插入占位符」下拉 → 选「插入签名」或「插入印章」。
3. 弹出小抽屉，只列出**已审核通过、且对你（当前用户/Key）可用**的签名/印章。
4. 点选一枚，光标处即插入一个图片占位块。

### 4.2 占位变量名即资源 ID

插入后，模板里生成的占位符**变量名就是资源 ID**：

```
{{ sig_a1b2c3d4e5f6 }}     ← 签名
{{ seal_0f1e2d3c4b5a6 }}   ← 印章
```

- 它和图片走**同一管线**，按资源记录的 `width_mm / height_mm` 插入，版式不漂移。
- 数据 JSON 里**不需要**手动给这个字段赋值——系统按 ID 自动注入对应 PNG。
- 未授权/未审核的资源**不出现在抽屉里**（不是置灰，是直接不出现）。

### 4.3 预览不扣次数

编辑器里实时预览（apply / preview）会把签章图渲染出来给你看效果，但**不消耗授权次数**。放心反复预览排版。

## 5. 审核机制（第一道关卡）

### 5.1 独立开关

路径：**管理中心 → 系统设置**，有两个独立开关：

- `review_signatures_enabled`（签名审核，默认 **关闭**）
- `review_seals_enabled`（印章审核，默认 **关闭**）

| 开关 | 行为 |
| --- | --- |
| **关闭（默认）** | 新建签名/印章**直接 approved**，立即可用，不进审核队列 |
| **开启** | 新建/重传 → **pending（待审核）**，进入「签章中心 → 审核队列」，由 admin 通过后才可用 |

> 开关切换即时生效，不影响已经通过的资源。

### 5.2 状态机

```
创建(上传/生成)
   │
   ├─ 开关 OFF ──► approved（直接可用）
   └─ 开关 ON  ──► pending（待审）
                        ├─► approved（admin 通过）
                        └─► rejected（admin 驳回，需改后重传回 pending）
approved ──► disabled（停用，立即从可用列表消失）
```

### 5.3 审核队列操作

路径：**签章中心 → 审核队列**（`/seals-center/review`，仅 admin）。

- 合并列出待审签名与待审印章，Tab 切换。
- **通过**：弹窗确认。
- **驳回**：必须填驳回意见，资源回到创建人手上，改后重传重新进队列。
- 审核动作全部留痕（写 `review.approve` / `review.reject` 审计 + `reviews` 流水）。

### 5.4 fail-closed

一旦开关开启，**任何处于 pending / rejected / disabled 的签名或印章，在生成时一律被拒**，返回：

- **HTTP 422** `signature_unavailable`，消息如"签名 xxx 未通过审核，不能用于生成"。

宁可拒、不可漏——这是合规底线，防止"未审核签章"流出去变成正式文档。

## 6. 授权机制（第二道关卡）

审核管"素材本身能不能用"，授权管"**这个调用方**能用它几次、用到什么时候"。两道独立、可叠加。

### 6.1 谁需要被授权

| 调用方 | 规则 |
| --- | --- |
| 资源 **owner 本人** | 始终可用，**不扣次数** |
| **admin** | 始终可用，**不扣次数** |
| 其他成员 / 其他 API Key | **必须显式授权**才能用，未授权 → 403 |

### 6.2 授权能授给谁

在签名/印章**详情页 → 授权管理**抽屉里，被授权对象可**多选**：

- 具体用户（`u_xxx`）；
- 具体 API Key（`ak_xxx`）。

### 6.3 授权策略（次数 + 时间窗口可组合）

一条授权承载一个组合策略：

| 项 | 含义 |
| --- | --- |
| `max_uses` | 总次数；`0` = 不限次数 |
| `valid_from` | 生效时间（空 = 立即） |
| `valid_until` | 失效时间（空 = 长期） |

三种常用配法（可叠加）：

- **单次授权**：`max_uses=1`，给某 Key 用一次就停。
- **次数授权**：`max_uses=10`，累计最多 10 次。
- **期限授权**：`valid_from` / `valid_until`，某时间段内有效。
- **叠加**："在 2026-12-31 前、限 5 次"——`max_uses=5` 且 `valid_until=2026-12-31`。

### 6.4 授权生命周期与状态

授权落库只有 `active` 行，以下状态是**查询时计算**出来的派生状态：

| 派生状态 | 条件 |
| --- | --- |
| `active` | 在时间窗口内 且（`max_uses=0` 或 `used_count < max_uses`） |
| `exhausted` | `used_count >= max_uses` |
| `expired` | 当前时间 > `valid_until` |
| `not_yet` | 当前时间 < `valid_from` |
| `revoked` | 被手动吊销 |

在授权管理抽屉里可以：

- **续期 / 加次数**（`grant.renew`）：延长 `valid_until` 或追加 `max_uses_delta`。
- **吊销**（`grant.revoke`）：立即失效。
- 查看**授权事件时间线**：授予 → 每次使用（扣减记录）→ 续期 → 吊销，全部流水留痕。

## 7. 什么时候扣次数、扣几次

| 场景 | 扣几次 |
| --- | --- |
| 一次生成任务同时出 docx + pdf（`format=both`） | 每个被引用的签名/印章**扣 1 次**（按 job 计，不按文件格式计） |
| 编辑器实时预览 `/apply`、`/preview` | **0 次** |
| owner / admin 使用 | **0 次**，不写使用记录 |
| 同一 `external_ref` 幂等重放 | **不重复扣**（扣减发生在任务首次渲染时，重放命中既有任务不重跑） |

扣减是数据库**原子操作**：`UPDATE grants SET used_count=used_count+1 WHERE id=? AND (max_uses=0 OR used_count<max_uses) AND (valid_until IS NULL OR valid_until>now())`。影响行数为 0 即拒绝——并发下不会超扣。

## 8. 常见拒绝与排查

| 现象 | 原因 | 排查/处理 |
| --- | --- | --- |
| 422 `signature_unavailable` | 引用的签名/印章是 pending / rejected / disabled | 去签章中心看资源状态；开关开启时等 admin 审核通过；或联系创建人重传 |
| 403 `grant_denied` reason=`unauthorized` | 当前用户/Key 对该素材**没有授权** | 联系 owner/admin 在授权抽屉里授予 |
| 403 `grant_denied` reason=`exhausted` | 授权次数用完 | 请 owner/admin 续期加次数 |
| 403 `grant_denied` reason=`expired` | 授权过了 `valid_until` | 请 owner/admin 延长有效期 |
| 403 `grant_denied` reason=`not_yet` | 授权 `valid_from` 还没到 | 等生效，或改窗口 |
| 编辑器抽屉里**找不到**某枚签名/印章 | 它未通过审核，或对你未授权 | 这是设计行为（不置灰、不出现）；找 owner/admin |
| 预览有签章，正式生成没扣次数 | 正常——预览不扣 | 以实际产出 docx/pdf 时的扣减为准 |

> 所有"用了哪个签名/印章、谁用的、扣了几次、被拒原因"都会写进**审计日志**（见《04 · 审计日志说明》），可追溯、可校验。
