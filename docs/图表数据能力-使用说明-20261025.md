# 铸版 · 图表数据能力（传参改图，样式不动）

> 2026-10-25 · 起因：「这里有一个折线图或者饼状图，我也能传入参数，把这个图标改掉（**注意只改数据不改样式**）」

## 一、一句话说清这个能力

模板里的图表，可以通过传参换掉**数字和文字**，但**配色、线宽、字体、图例、坐标轴、网格线一个像素都不动**。

技术上的做法是只重写图表 XML 里的「数据缓存」节点，样式节点整棵树都不碰。这不是"小心地改"，是**结构上够不着**——`chartdata.py` 从不进入 `c:spPr` / `c:txPr` / `c:dLbls` / `c:axId` 这些样式分支。

## 二、能力边界

| 维度 | 能否改 | 原因 |
|---|---|---|
| 分类名（X 轴 / 饼图扇区名） | ✅ 数量可变 | 只重写 `c:cat` 缓存 |
| 数值 | ✅ 数量可变 | 只重写 `c:val` 缓存 |
| 系列名（图例文字） | ✅ | 只重写 `c:tx` 缓存 |
| **系列个数** | ❌ | 增删会让 `c:dPt`（单点样式覆盖）索引错位；新系列没有 `spPr`，只能落默认配色＝**样式被改** |
| **图表类型** | ❌ | 换类型必须重建 `plotArea`，等于换掉整张图 |
| 任何样式 | ❌ | 从不触碰 `spPr` / `txPr` / `dLbls` / `ax` |

系列数不一致时**直接报错，绝不静默画错**：

```json
{"error": {"code": "chart_invalid", "message": "模板有 2 个系列（2025、2026），传入 1 个。只改数据不改样式，不能增删系列"}}
```

数据点（分类）可以自由增删——从 4 个季度改成 5 个月份没问题，图表会自动重排，样式不受影响。

## 三、怎么用

### 3.1 接口传参

模板扫描后会多出若干 `kind: "chart"` 的变量，变量名取 `chart_<图表标题>`：

```bash
curl -X POST https://zb.kinghtxg.com/api/v1/render \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{
    "template_code": "sales-report",
    "format": "pdf",
    "sync": true,
    "data": {
      "chart_季度销售额": {
        "categories": ["1月", "2月", "3月", "4月", "5月"],
        "series": [
          {"name": "去年", "values": [80, 150, 240, 190, 320]},
          {"name": "今年", "values": [120, 190, 300, 260, 410]}
        ]
      }
    }
  }'
```

三件事值得注意：

1. **不传就不改**。省略 `chart_xxx` 时沿用模板原有数据，业务上完全合理（例如报表只要改文字、图沿用上月）。所以图表变量是 `required: false`。
2. **系列名可以改**，改了就换图例文字，但图例的位置/字体/颜色不变。
3. **散点图**用 `xVal` / `yVal` 而不是 `cat` / `val`，接口层的 payload 形态一致，内部已分别处理。

### 3.2 网页操作

工作台左栏「图表数据」区会列出识别到的每张图（图表类型 · 系列数 · 数据点数），点「改数据」打开表格抽屉：

- 表头可直接改系列名
- 网格里逐格填数字，留空 / 非数字会实时提示
- 分类行可增删
- 保存后写回 JSON，跟其他变量一起提交

编辑器画布上图表显示为一张「图表卡片」（显示类型、标题、系列数、数据点、前 8 个分类），**不是空段落**——这是刻意的：那张段落里挂的是 `<w:drawing>`，一旦当普通段落回写文字，整张图会被删掉。

## 四、为什么"两份数据"都要写

图表有**两个**数据源：

| 位置 | 作用 | 只改一处的后果 |
|---|---|---|
| `word/charts/chartN.xml` 的 `c:numCache` | 渲染时显示的缓存 | 页面好看，但用户点「编辑数据」看到旧数字 |
| `word/embeddings/*.xlsx` 内嵌工作簿 | "数据是真的"的证据 | 反之：Excel 里新、页面上旧 |

所以 `_sync_workbook()` 会按 `c:f` 声明的区域（`Sheet1!$A$2:$A$5`）把同样的值写进内嵌工作簿，横向、竖向两种排布都支持。

## 五、样式不变的机器可验证定义

"没改样式"不能靠目测。`chartdata.style_fingerprint()` 给出可断言的证据：

```python
def style_fingerprint(chart_xml: bytes) -> str:
    """深拷贝整棵树，剥掉纯数据节点（cache/pt/ptCount/f），剩下的规范化输出。
    数据变了指纹必须不变 —— 这就是"样式没被改"的机器可验证事实。"""
```

测试 C11 断言改数据前后指纹逐字节一致；C12 断言 `document.xml`、`styles.xml` 字节完全不变，只有 `chart*.xml` 和内嵌 xlsx 被改动。

## 六、渲染顺序的坑

图表数据**必须**在 `docxtpl` 渲染**之后**写。`docxtpl` 会整包重写 docx，先改 `chartN.xml` 会被它的保存动作覆盖掉，表现为"参数传了但图没变"。

## 七、排查指南

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| `download_url` 下载到 410 / 一个 82 字节的 JSON | `format=pdf` 的任务没有 docx，旧版响应把主链接固定指向 docx | 已修（`docURLs()`）：PDF-only 时主链接自动带 `?format=pdf` |
| `format_not_available` | 要的格式这份文档没生成 | 按 `job.format` 判断该用哪个链接；`pdf_download_url` 只在生成过 PDF 时出现 |
| 传了数据但图没变 | 图表变量名写错（是 `chart_<标题>` 不是标题本身） | 先 `GET /api/v1/templates/{id}` 看 `variables` 里 `kind=chart` 的 `name` |
| `chart_series_mismatch` | 系列数跟模板不一致 | 按模板的系列数传；要加系列只能改模板 |
| 饼图多出一块颜色很怪 | 模板只为前 N 个点定义了 `dPt` 颜色，新增的分类落 LibreOffice 自动配色 | 正版 Office 里同样如此；这是模板数据决定的，不是本能力引入的 |

## 九、压缩炸弹防护

图表解析会读内嵌工作簿，属于用户可控的 zip 内容，因此设了上限：

```python
MAX_CHART_PART_BYTES = 8 * 1024 * 1024    # 单个 chartN.xml
MAX_WORKBOOK_BYTES   = 24 * 1024 * 1024   # 内嵌 xlsx
MAX_SHEET_XML_BYTES  = 32 * 1024 * 1024   # 单个 sheet.xml
MAX_POINTS           = 2000               # 每系列数据点
MAX_CATEGORY_LEN     = 200                # 单个分类名长度
```
