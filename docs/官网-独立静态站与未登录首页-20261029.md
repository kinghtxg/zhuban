# 官网：独立静态站 + 未登录首页

> 生效：2026-10-29 · 相关文件：`site/index.html`、`site/landing.js`、`embed.go`、`server/internal/api/landing.go`

## 1. 需求与结论

要一个能对外看的官网，动效要够、卖点要写全、露出 GitHub 地址；并且这个官网要成为
**产品未登录时的首页**（否则第一次打开域名的人只看到一个登录框）。

做完后的形态是「一份源码，两种用法」：

| 用法 | 入口 | 说明 |
|---|---|---|
| 未登录首页 | `GET /` | 无有效会话时返回官网；有会话返回工作台 |
| 永久官网地址 | `GET /welcome` | 登录与否都给官网（发给同事用的链接） |
| 独立静态站 | 直接托管 `site/` | 零构建：拷贝即用，可放 GitHub Pages / OSS / nginx |

## 2. 为什么判定放在服务端，而不是前端路由

前端也做得到（未登录时渲染一个 `Landing` 组件）。没这么做的两个理由：

1. **抓取**。搜索引擎与分享卡片需要一个真实 HTML 文档。SPA 吐出来的是一张空壳，
   标题、描述、正文全要靠 JS 补，很多抓取器不会等。
2. **首屏**。未登录访客的第一跳本来是「加载 JS → 发现没登录 → 跳登录页」。
   服务端判定只需读一次会话就能少一次跳转，也少一次"闪一下登录框"。

代价是深链接要显式排除：只有 `GET /` 参与判定，`/templates`、`/jobs/{id}` 等仍走 SPA。
`handleRoot` 里就三行——路径不是 `/` 就交回 `handleSPA`。

## 3. 三个必须知道的约束

### 3.1 脚本不能内联（CSP）

全站 CSP 是 `script-src 'self'`（这一条是整个 CSP 里最值钱的，见 `security.go` 注释）。
所以官网的 JS 拆成 `site/landing.js`，由 `GET /landing.js` 提供。

**踩过的坑**：页面用 `file://` 直接打开时没有 CSP，内联脚本跑得好好的；
一旦由产品提供，脚本被拦，页面"看起来正常但什么都不动"，只有控制台里有提示。
所以验收不能只看 HTML 有没有吐出来，要在真实 CSP 下确认动效确实在跑
（`server/internal/api/landing_test.go` 与本地实测都覆盖了这一点）。

### 3.2 链接是绝对地址，由服务端改写

独立托管时 `/login` 没有对应路由，所以站内链接写成 `https://zb.kinghtxg.com/...`。
被产品自己提供时，若不改写，自建实例的用户点「进入控制台」会被送到官方实例——
在私有化部署里这是"数据出境"级别的尴尬。

改写方式：`serveLanding` 把占位域名换成 `EXTERNAL_BASE_URL`（没配则用请求的 Host）。
页面上还有一处只写主机名（首屏那句「线上运行 xxx」），单独再换一次。
尾斜杠会被 `TrimSuffix` 去掉，避免拼出 `//login`。

### 3.3 不要放进 `web/dist`

`web/dist` 是前端构建产物，`npm run build` 会覆盖整个目录。官网放在仓库根的 `site/`，
用独立的 `//go:embed all:site` 内嵌。`deploy/pack.sh` 也会把它一起打包（未排除）。

## 4. 动效清单（都尊重 `prefers-reduced-motion`）

| 效果 | 实现 | 降级 |
|---|---|---|
| 星图粒子背景 | canvas，两点距离小于阈值连线；`visibilitychange` 时停 RAF | 不绘制 |
| 极光光斑 | 三个 `radial-gradient` + `drift` 关键帧 | 静止 |
| 首屏终端卡逐行日志 | 定时器逐行加 `.in`，进度条同步推进，跑完 4.2s 重播 | 一次全出，进度 100% |
| 卡片跟随鼠标高光 | `pointermove` 写 `--mx/--my`，`radial-gradient` 跟随 | 恒常高光 |
| 终端卡 3D 微倾 | `perspective` + 鼠标位置算 `rotateX/Y` | 不动 |
| 滚动入场 | `IntersectionObserver`，同组元素按序错峰 ≤420ms | 直接显示 |
| 数字滚动 | `requestAnimationFrame` + easeOutCubic，1.5s | 直接显示终值 |
| 滚动进度条 / 导航高亮 | `scroll` 被动监听 + `getBoundingClientRect` | 保留（无动画） |

`prefers-reduced-motion` 的判定只有一处（`reduce` 变量），所有动效都看它——
不是零散地在各处写媒体查询，否则一定会漏掉一两个。

## 5. 验收记录

本地（`HTTP_ADDR=127.0.0.1:18199`，sqlite）：

```
GET /            （无 cookie） → 200  text/html  <title>铸版 · 把 Word 模板变成产线</title>
GET /            （有 cookie） → 200  text/html  <title>铸版 · Word 模板渲染平台</title> + id="root"
GET /welcome     （有 cookie） → 200  官网
GET /landing.js               → 200  application/javascript; charset=utf-8  Cache-Control: max-age=3600
链接改写                       → href="http://127.0.0.1:18199/login"，页面内 zb.kinghtxg.com 残留 0 处
真实 CSP 下                    → 计数 286/288 滚动中、canvas 有像素、进度条 405px、28 个 reveal 已显示、无 CSP 拦截日志
```

自动化：`server/internal/api/landing_test.go` 7 个用例（匿名/登录分流、`/welcome`、链接改写、
脚本 MIME 与缓存头、嵌套路径拒绝、会话撤销后回到官网）。

布局审计（playwright，1440 / 820 / 390 三档）：无横向溢出、无元素越界、无 console 报错，
全部 `.reveal` 元素滚动后都能显示。
