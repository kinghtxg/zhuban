# 铸版 · 模板元素支持能力矩阵

> 2026-10-25 · 起因：「该模板含暂不支持的元素，已以只读模式打开。请在 Word 中处理后重新上传。**应该要所有元素都支持啊**」

## 一、先把两件事拆开

用户看到的提示把两个完全不同的东西混成了一句。这是这次问题的根源。

| 链路 | 做什么 | 依赖什么 | 失败后果 |
|---|---|---|---|
| **编辑链路** `/parse` → `/apply` | 把 docx 解析成「段落/标题/表格/占位符」的块模型，在网页里改结构 | `word/document.xml` 的**块级结构** | 网页里改不了排版，**文档照样能生成** |
| **生成链路** `/scan` → `/render` | 扫描 `{{占位符}}` → 填数据 → docxtpl 替换 → 出 docx/PDF | **只认占位符文本**，完全不看块结构 | 生成不出来，这是真故障 |

用户撞到的是**编辑链路**整份解析失败，提示却说成"部分元素不支持 + 已在只读模式打开"——三处都不实：

1. 不是"部分不支持"，是整个解析挂了；
2. 根本没有只读模式，页面压根没渲染；
3. 真实的失败原因（`loadError`）拿到了却没显示。

结果用户被引导去 Word 里反复删元素，删几轮也不会好。

## 二、当前实际支持矩阵

「编辑」指能不能在网页里改；「生成」指填数据导出 docx/PDF 时这块内容会不会正确带出去。

| 元素 | 网页显示 | 网页编辑 | 生成时 | 说明 |
|---|---|---|---|---|
| 段落 / 标题（h1–h9） | ✅ | ✅ | ✅ | 标题层级按 `styles.xml` 的 `outlineLvl` 解析，含 `basedOn` 继承链 |
| 表格（行列、单元格） | ✅ | ✅ 增删行 / 改单元格 / 标记循环行 | ✅ | `{%tr for %}` 循环行支持 |
| 列表（编号/项目符号） | ✅ | ✅ | ✅ | 连续 `numPr` 段落聚合为一个列表块 |
| 行内图片占位 | ✅ | ✅ 换图 | ✅ | 从 `wp:extent` 读宽高（mm） |
| 二维码占位 | ✅ | ✅ | ✅ | `qr_` 前缀 |
| 富文本/Markdown 占位 | ✅ | ✅ | ✅ | `rich_` / `html_` / `md_` 前缀 |
| 签名 / 印章占位 | ✅ | ✅ 选章 | ✅ | `sig_` / `seal_` 前缀，服务端 sigauth 注入 |
| **内联图表（折线/饼/柱状等）** | ✅ **画布显示为图表卡片** | ✅ **只改数据**，样式不动 | ✅ 数据缓存 + 内嵌工作簿双写 | 见 `docs/图表数据能力-使用说明-20261025.md`；系列数不可增删 |
| **文本框内文字**（`w:txbxContent`） | ✅ **本轮起显示原文** | ❌ | ✅ 原样保留 | 常见于公文封面、受控标识框 |
| 形状 / VML 图片框（`w:pict`） | ⚠️ 显示"_此处为图形_"+说明 | ❌ | ✅ 原样保留 | 老式 Word 艺术字、线条、图文框 |
| 浮动锚定对象（`wp:anchor`） | ⚠️ 同上 | ❌ | ✅ 原样保留 | 环绕排版的图片 |
| 页眉 / 页脚 | ❌ 不在编辑器画布内 | ❌ | ✅ **占位符本轮起能被扫描** | 见下文缺陷 2 |
| 脚注 / 尾注 | ❌ | ❌ | ✅ 原样保留 | 占位符可扫描，但画布不展示 |
| 目录域（TOC） | ✅ 显示为文本 | ⚠️ 建议不直接改 | ✅ | 改文字会破坏域，未改动则一字不碰 |
| 批注 / 修订痕迹 | ❌ | ❌ | ✅ 原样保留 | 只读部件 |
| 公式（OMML） | ⚠️ 显示为 img 位置 | ❌ | ✅ | 不解析公式树 |
| 宏（.docm） | — | — | 🚫 上传即拒 | 安全红线 |

**一句话**：编辑器覆盖的是 `word/document.xml` 的 **body 直属节点**。超出这个范围的东西一律"原样保留、不参与在线排版"，并且**不参与** = **不会坏**。docapply 对 `unsupported` 块的处理是 `return`（直接跳过），一个字节都不碰。

## 三、本轮实际改了什么

### 缺陷 1：整份解析失败被说成"部分元素不支持"（真故障，阻断使用）

- `render-service/app/main.py`：`/parse` 加 `etree.XMLSyntaxError` + 通用 `Exception` 兜底，转成 `SecurityError("template_invalid", …, 422)` 并打完整 traceback。此前三种输入（缺 `word/document.xml`、`document.xml` 非法 XML、根本不是 zip）全部抛裸异常 → FastAPI 500 → 前端只能给一句含糊提示。
- `web/src/pages/editor/EditorPage.tsx`：失败页重写。如实展示 `loadError` 原文；说明只影响「在线改结构」；并**降级为变量编辑视图**——因为 `current_version.variables` 是导入时独立扫描落库的 JSONB，与结构解析无关。解析挂了，变量清单、示例数据、填数据生成照样能用。

### 缺陷 2：页眉/页脚里的占位符完全扫描不到（更严重的隐性故障）

`scanner.py` 的 `_extract_tokens` 只读 `word/document.xml`。而 `preprocess.py` 早就已经在修 header/footer 的跨 run 拆分——两边口径不一致。

后果不是"少一个变量"，是**生成出来的文档会在页眉里原样留着 `{{报告编号}}`**。中文公文/测评报告把「报告编号」「受控标识」「单位名称」放页眉是常态，这批模板会整体失效，且用户完全没有察觉途径（变量列表里就没有这一项）。

已改为扫描 `document.xml` + `header*.xml` + `footer*.xml` + `footnotes.xml` + `endnotes.xml`，单个部件坏了只记 warning 不中断。

### 缺陷 3：单个坏元素会拖垮整份文档

`parse_docx` 主循环此前没有异常隔离——一个段落/表格解析抛错，整份模板就打不开。

现在每个 body 直属节点先快照（`blocks` 长度、`p_counter`、`tbl_counter`），解析抛异常就回滚到快照、把它自己降级成一个 `unsupported` 块再继续。**id 仍按 body 顺序连续分配**（`p0 / t0 / p1`），保证 `/apply` 侧的 id 对齐不被破坏。回归测试：`render-service/tests/test_parse_robust.py`（8 项）。

### 缺陷 4：不可编辑元素只显示一个空白方块

前端原来渲染成 `[需在 Word 处理] 文本框（w:txbxContent）`，用户既看不到盒子里写了什么，也不知道到底该去 Word 改什么（其实根本不用改）。

现在 `_unsupported_info` 把盒内原文提取出来塞进块的 `text` 字段，前端显示「原文 + 一行说明为什么不可编辑」。文案也从「需在 Word 处理」改成「随文档原样保留，不参与在线排版」。

## 四、为什么做不到"所有元素都能在线编辑"

docx 的元素空间不是有限集合：OOXML 规范有上千个元素，Word 自己每年还在加；相邻元素组合出的排版语义（环绕方式 × 表格嵌套 × 分节 × 域）远比元素本身多。任何"全支持"的承诺都做不到，商业产品（含 Word Online）也一样——你在 Word Online 里打开一份带复杂图文框的文档，它同样会提示降级。

真正要做到的是**边界清晰 + 边界内不丢东西**：

1. **不支持的，一个字节都不碰**（已做到，`docapply` 对 unsupported 直接 return）；
2. **不让局部问题升级成全局问题**（本轮做到，异常隔离）；
3. **不让用户猜**——看得见盒内是什么、知道影响哪一块、知道还能做什么（本轮做到）。

## 五、遗留（按价值排序）

| # | 项 | 影响 | 量级 |
|---|---|---|---|
| 1 | 页眉/页脚进编辑器画布（只读展示 + 占位符可视化） | 中：用户现在不知道页眉里有变量，虽然变量清单里能看到了 | 中 |
| 2 | 文本框内文字做成可编辑（需要给嵌套 `w:p` 单独寻址） | 中：公文封面文本框很常见 | 大 |
| 3 | 前端主包 4.6 MB（gzip 1.23 MB）未做 code split | 中：首屏慢，公网可用性打分被拉低 | 小 |
| 4 | `/metrics` 与 OpenAPI 文档仍返回 SPA 首页 | 中：可观测性缺口 | 小 |
| 5 | 目录域（TOC）在编辑器里当普通文本处理，改动会破坏域 | 低：不改就没事 | 小 |
