# 签章现场出图：引用字体 + 签署时间在输出那一刻求值（2026-10-26）

## 1. 需求原文

> 「传入的时候，尤其是时间这一块，你要由比如引用字体编号加时间，就可以直接在输出的时候输出签字版本的时间」

拆成三条可验证的行为：

1. 调用方在 data 里**引用**一份签章资源，并给出字体编号（以及可选的署名）；
2. 同时给出一个「时间」，但**不是**给一个具体时刻，而是给「怎么算」；
3. 服务端在**输出那一刻**把字 + 时间画成一张签字图，插进文档。

## 2. 之前做不到的根因

签章资源（`models.Signature`）存的是**一张已经出好的图**（`FilePath` 指向 PNG），
`sigauth.resolveOne` 只读 `FilePath / WidthMM / HeightMM` 就把整张图 base64 进 data。
后果是三条连锁的：

| 现象 | 原因 |
|---|---|
| 同一张签名图用在三份文件上，三份印同一个签署时间 | 时间在资源创建那一刻就被烤进像素 |
| 想在合同上印「出具时间」就得每次重建资源 | 没有「出图参数」这一层，只有「图」 |
| 资源库迅速变成「张三-隶书-0925」「张三-隶书-0926」 | 换字体只能重建资源（FontID 存了但没人读） |

`FontID`、`SignerName` 其实一直在库里躺着，只是 `resolveOne` 从来不读；
`render_service/app/signature.py` 也早就有 `with_timestamp` 能力，但只能**预生成**。
缺的是中间这一层：把「引用哪份资源」和「怎么出图」分开表达。

## 3. 新形态

```json
{
  "sig_审核人": {
    "$sig": "sig_a1b2c3d4e5f60718",
    "font": "liu-jian-mao-cao",
    "with_timestamp": true,
    "timestamp": { "$date": "now", "format": "%Y-%m-%d %H:%M" },
    "timestamp_prefix": "签署时间：",
    "width_mm": 60
  }
}
```

- `$sig` / `$seal` 是**标记**（业务数据里几乎不会有 `$` 开头的键，所以看到就一定是本模块的）。
- 字体、署名**默认继承资源**，写了则覆盖。于是同一份资源既当素材又当授权凭证，
  换字体不用重建资源——这是「资源库膨胀」那条的直接解药。
- 只改 `width_mm` / `height_mm` **不触发出图**（读原图就够），编辑器每次 apply 都走这里，能省一次往返。
- 老形态（`"sig_x": "sig_abcd1234"`、`"sig_x": ""`、内联图片对象）行为完全不变。

### 3.1 授权口径一格没动

`$sig` 指向的资源就是被校验、被扣次数的那一条：`status=approved`、未软删、owner/admin
放行、否则原子扣减一条 active grant。**参数对象不能凭空获得权限**——
否则传个 `font` 就能自己画一个签贴上去，这是本轮最要紧守住的一条，
单测 `TestSigRef_ParamsCannotBypassGrant` 同时断言了「返回 403」和「渲染服务一次都没被调用」
（不能出现「白画一张图再报错」）。

## 4. 时间为什么在渲染服务求值，而不是 Go

`timestamp` 里的 `{"$date":...}` **原样**转交给 render-service，由它在画 PNG 那一刻求值。
Go 侧一个字节的时间计算都不做，理由：

- `dateexpr` 已经有一份完整实现（默认 `Asia/Shanghai`、`offset_*`、`last_day_of_month`、严格校验）。
  Go 再实现一遍就是第二份「北京时间到底怎么算」的答案，两份迟早不一致；
- 时间语义要和文档里其它日期字段（`{{ 报告日期 }}`）**完全一致**，否则同一份文书上
  签名时间与报告日期可能差 8 小时；
- 单测 `TestSigRef_GeneratesWithTimestampExpr` 直接断言 Go 传过去的
  `timestamp_expr` 里仍然带着 `"$date":"now"` 原文——这是「Go 没有偷偷算一遍」的证据。

时间来源优先级：`timestamp_expr`（表达式）> `timestamp`（ISO 8601 字面）> 容器当下时间。
两者同时给 → 422（静默挑一个等于让用户以为生效的是另一个）。

同时修了一个**老的静默降级**：`_parse_timestamp` 以前解析失败会退回「现在」，
于是 `2026-13-45` 会被印成今天、校验还是绿的。现在一律 422 `invalid_timestamp`。

## 5. 一个连带修掉的真 bug

第一次端到端跑出来：非法时间返回的是 **500 internal_error**，不是 422。
原因是 `sigauth.buildImage` 用 `fmt.Errorf("现场生成签名失败：%w", err)` 包了一层，
而 `api.renderErr` 用的是**类型断言**（`err.(*render.Error)`），一包就掉到 500 分支，
把用户的输入错误说成「服务内部错误」。

已改成 `errors.As`。这条错误映射是所有渲染调用共用的，顺手把同类隐患一起修了。


`PASS 宽度都是 60mm` 这一条是「不破坏格式」的直接守卫：时间那一行只让图变高，
不改变摆放宽度，因此不会把表格列顶开。

## 7. 边界（没做到的，如实写）

1. **只做了「印时间」一个开关**。工作台（`/templates/:id/playground`）的「签名与印章」每行多了一个
   `印时间` 按钮：点一下把值从 `"sig_xxx"` 换成参数对象，再点回到字符串形态。
   **字体 / 署名 / 前缀 / 尺寸仍需手写 JSON**（JSON 编辑框就在旁边），没有做成表单；
   在线模板编辑器（画布）里也没有参数入口。
2. **印章只支持换尺寸/单位名/章名/形状/半径**，不支持时间（`$seal` 带 `with_timestamp` 直接 422）——
   公文规范里印章不印时间，这是刻意的限制，不是没做完。
3. **时间只精确到秒且只取一次**。批量 500 份在 18:59:59 与 19:00:00 之间会分成两组时间，
   与 `dateexpr` 的既有行为一致（同一份 data 一次请求内一致，跨请求各自取当刻）。
4. **出图无缓存**。带时间的图每次都要重画；不带时间但改了字体也一样。
   PIL 画一张约 10~20ms，比对 200 次/秒的场景够用，但没有做缓存层。
5. **`$sig` 的值必须是合法资源 ID**（`^(sig|seal)_[0-9a-zA-Z]{6,}$`）；
   想引用一份「不属于自己也没有授权」的资源照旧 403，没有后门。
6. **审核流未变**：现场出图用的是资源已有授权，不产生新的审核动作。
   也就是说「被授权用这张签」等价于「被授权用这张签的任何字体/时间组合」——
   如果客户要求「换字体需重新审批」，这里需要再加一层（当前没有）。
