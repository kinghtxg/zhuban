## 1. 最快启动（镜像）

镜像发布在 GitHub Container Registry（公开，拉取不需要登录）：

| 镜像 | 内容 |
|---|---|
| `ghcr.io/kinghtxg/zhuban` | Go 主服务：API + 前端 + 官网 + 安装向导 |
| `ghcr.io/kinghtxg/zhuban-render` | Python 渲染服务：docxtpl + LibreOffice |
| `postgres:16-alpine` | 数据库（官方镜像） |

```bash
git clone https://github.com/kinghtxg/zhuban.git && cd zhuban
cp .env.example .env

# 三个密钥必须自己生成：留空时 compose 会直接拒绝启动
#   POSTGRES_PASSWORD / SIGNED_URL_SECRET / AUTH_SECRET
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 16)|" .env
sed -i "s|^SIGNED_URL_SECRET=.*|SIGNED_URL_SECRET=$(openssl rand -hex 32)|" .env
sed -i "s|^AUTH_SECRET=.*|AUTH_SECRET=$(openssl rand -hex 32)|" .env

docker compose -f docker-compose.ghcr.yml up -d
```

打开 `http://<服务器地址>:18100`，会直接被送到**安装向导**（见第 3 节）。

> ⚠️ **装完之前别把端口暴露到公网**：首次打开页面时，谁先填完向导谁就是管理员。

只想先在本机看一眼，把 `docker-compose.ghcr.yml` 里的端口映射改成
`127.0.0.1:18100:8100` 即可。

### 中国大陆构建/拉取的注意事项

镜像在境外构建，拉取可能很慢。拉取慢用代理或镜像加速；**自己构建**时必须换源，
否则 LibreOffice 那一层会卡到超时：

```bash
# 写进 .env，docker-compose.yml（源码构建）会自动读取
APT_MIRROR=mirrors.tencentyun.com
PIP_INDEX=https://mirrors.tencentyun.com/pypi/simple
NPM_REGISTRY=https://registry.npmmirror.com
GOPROXY=https://goproxy.cn,direct
APK_MIRROR=mirrors.tencentyun.com
```

## 2. 从源码构建

改了代码、或想跑未发布的分支时用这份。三个服务全部本地构建：

```bash
cp .env.example .env      # 同上，填三个密钥
docker compose up -d --build
```

与镜像版的差别只有 `image:` / `build:` 两行；容器名也不同
（`docforge-*` vs `zhuban-*`），所以**不要在同一目录下同时起两份**。

构建时版本号会被编进二进制（页脚、`/api/v1/version`、更新检查都读它）：

```bash
APP_VERSION=3.4.0 APP_COMMIT=$(git rev-parse --short HEAD) \
APP_BUILD_TIME=$(date -u +%Y-%m-%dT%H:%M:%SZ) \
docker compose up -d --build
```

不传就是 `dev`。**`dev` 版本的更新提示不会弹**——本地构建的版本号没有可比性，
拿它去和线上 Release 比大小只会制造困惑。

## 3. 首次安装向导

数据库为空时，访问 `/` 会被 302 到 `/install`，三步：

1. **管理员账号**（必填）：用户名、密码、显示名（可选）、邮箱（可选）
2. **邮件服务**（可跳过）：SMTP 主机/端口/加密/账号/发件地址/允许投递的域名。
   这一页可以点「跳过」，之后在「管理中心 → 邮件」里再配；不配也能用，
   下载、直链、API 回调都不受影响。
3. **完成**：显示访问地址、版本、邮件是否已配置。

装完之后：

- `/install` 与 `/install.js` **永久 404**；
- 释放到 `volumes/install/` 的那份页面会被服务端删除；
- 想重装只能清空数据库（`docker compose down -v` 会连带删掉全部数据，谨慎）。

> 为什么是「删除」而不是「隐藏」：一个还能打开的安装页，在空库上等于
> 任何人都能重建管理员。所以它不是一个被藏起来的路由，是文件层面不再存在。

安装向导的页面文件是纯静态的，可以在安装前直接改
`volumes/install/index.html` 换成自己的欢迎语（下次启动会被内嵌版本覆盖）。

## 4. 反向代理与 HTTPS

产品自己不做 TLS，前面必须有一层反代（nginx / Caddy / 云 WAF）。仓库内有
`deploy/nginx-zb.conf.example` 可参考，关键几条：

```nginx
location / {
    proxy_pass http://127.0.0.1:18100;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 50m;          # 模板与字体上传
}

# 预览是 SSE/长连接，别让默认 60s 掐断
proxy_read_timeout 300s;
```

同时把 `.env` 里的 `EXTERNAL_BASE_URL` 改成用户浏览器里看到的地址
（`https://zb.example.com`）。这一项决定签名直链、OIDC 回调、接入示例里的域名，
写错了会出现「链接指向 localhost」这类只有别人访问时才暴露的问题。

来源 IP：只有对端命中 `TRUSTED_PROXIES` 时才采信 `X-Forwarded-For`。
默认信任本机与私网段（适配 Docker/Nginx 同机部署）。**直接暴露公网且无代理时**
必须设 `TRUSTED_PROXIES=none`，否则任何人都能用一个请求头伪造来源 IP，
绕过登录限流。

## 5. 备份与恢复

要备份的只有两样：**数据库**和 `volumes/`（模板文件、产物、字体、签章资源）。

```bash
#!/usr/bin/env bash
# /opt/zhuban/backup.sh —— 每日 03:30 由 cron 跑，保留 7 天
set -euo pipefail
cd "$(dirname "$0")"
STAMP=$(date +%F)
mkdir -p backup
docker compose -f docker-compose.ghcr.yml exec -T postgres \
  pg_dump -U "${POSTGRES_USER:-zhuban}" "${POSTGRES_DB:-zhuban}" \
  | gzip > "backup/db-$STAMP.sql.gz"
tar czf "backup/volumes-$STAMP.tar.gz" -C . volumes
find backup -name '*.gz' -mtime +7 -delete
```

**备份是否可用，只有"能恢复"才能证明**。至少每月验一次：

```bash
# 1) 先看归档完不完整（不需要真恢复）
gunzip -c backup/db-2026-10-30.sql.gz | pg_restore -l /dev/stdin >/dev/null && echo "归档可读"

# 2) 真恢复到临时库，确认表与数据都在
docker compose exec -T postgres createdb -U zhuban restore_test
gunzip -c backup/db-2026-10-30.sql.gz | docker compose exec -T postgres psql -U zhuban -d restore_test
docker compose exec -T postgres psql -U zhuban -d restore_test -c "select count(*) from templates; select count(*) from documents;"
```

只做 `pg_dump` 从没恢复过，等于没有备份——这类事故的共同点是
「文件在、且是 0 字节」或「能读到表结构、数据表是空的」。

## 6. 升级

**镜像版**（推荐）：

```bash
cd /opt/zhuban
docker compose -f docker-compose.ghcr.yml pull
docker compose -f docker-compose.ghcr.yml up -d
```

**源码版**：

```bash
git pull && docker compose up -d --build
```

升级前先备份（第 5 节）。数据库迁移在启动时自动执行（只增列/建表，不删列）。

升级后确认三件事：

```bash
curl -s http://127.0.0.1:18100/api/v1/healthz
curl -s http://127.0.0.1:18100/api/v1/version     # 版本号对不对
docker compose ps                                  # 三个服务都 healthy
```

## 7. 更新提示

联网的实例会在登录后 2.5 秒查一次 GitHub 上的最新 Release；
有更高版本时**右下角**出现一张卡片：`当前版本 → 新版本`，附发布说明摘要，
「查看更新」跳到发布页，「忽略此版本」不再提示该版本（下个版本仍会提醒）。

口径：

- 只查版本号，**不下载、不自动替换二进制**。服务器上自动换二进制最容易把服务搞挂
  （下到一半、权限不对、正在跑的任务被中断），那属于包管理器与新部署的事。
- 服务端有 6 小时缓存，外部打不穿；查询失败时保留上次结果并标记 `stale`，
  前端不会把「没查成」当「已是最新」。
- 预发布（`-rc1`）不提示：服务器升级应该是明确动作。
- 隔离内网（没有 `api.github.com`）请设 `UPDATE_CHECK=false`，
  否则只是每 6 小时在日志里留一条失败记录。
- 私有部署想指向自己的 fork：`UPDATE_REPO=<owner>/<repo>`。

## 8. 配置项速查

完整清单见 `.env.example`（每一项都有注释）。最常改的几个：

| 变量 | 默认 | 说明 |
|---|---|---|
| `EXTERNAL_BASE_URL` | `http://localhost:18100` | 对外基址，**必须**是用户浏览器里的地址 |
| `WEB_PORT` | `18100` | 宿主映射端口 |
| `AUTH_SECRET` | 空（必填） | 会话 cookie 签名；换掉等于全员下线 |
| `SIGNED_URL_SECRET` | 空（必填） | 签名直链 HMAC；换掉等于旧直链全失效 |
| `RETENTION_DAYS` | `7` | 产物保留天数，到期清理 |
| `SESSION_TTL_DAYS` | `7` | 会话有效期 |
| `ALLOW_REGISTER` | `false` | 自助注册（注册后需管理员审核） |
| `TRUSTED_PROXIES` | 本机+私网 | 采信 `X-Forwarded-For` 的对端名单；无代理设 `none` |
| `SEED_BUILTIN` | `true` | 是否内置示例模板 |
| `UPDATE_CHECK` | `true` | 是否检查新版本 |
| `EMAIL_ALLOWED_DOMAINS` | 空 | 允许 API 投递的收件人域名；**留空=拒绝**（fail-closed） |

## 9. 排错

**容器起来了但端口连不上**
Go 服务启动时会先打一行版本日志。如果这行都没出现，是容器根本没起来，
看 `docker compose logs web`。历史上最常见的是数据库密码不对（`28P01`），
多半是 `.env` 被覆盖成了开发配置。

**页面能打开，但所有按钮都不动**
CSP 是 `script-src 'self'`：任何内联 `<script>` 都会被浏览器拦掉，
只在控制台报错。二次开发时把脚本放成独立文件。

**模板播种失败 / 一直"待扫描"**
render 服务没就绪。`docker compose logs render` 看 LibreOffice 是否起来了；
它首次启动要建字体缓存，健康检查给了 90 秒 `start_period`。
播种是异步的，不影响主服务启动——一会自己会补扫。

**上传成功但 PDF 打不开 / 只有几百字节**
先看响应体的 `download_url` 指向哪个文件。历史上出过一次
「任务只要 PDF，链接却写死指向 docx」，返回的是 410 错误 JSON（82 字节）。

**产物目录 permission denied**
`volumes/` 在 Linux 上默认 root 属主，而容器以 uid 10001 运行。
重新跑一次 `init-volumes`：

```bash
docker compose run --rm init-volumes
```

**容器出不了网（OIDC Discovery 失败、更新检查全红）**
先查 Docker 的 NAT 规则是否丢失：

```bash
iptables -t nat -L POSTROUTING
```

为空且 `FORWARD` 是 `DROP` 就是它。`systemctl restart docker` 重建规则。
